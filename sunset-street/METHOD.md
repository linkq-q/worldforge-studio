# 单张街景插画 → Three.js 重建：方法与验证记录

## 交付与边界

入口：开发服务上的 `/sunset-street/`。启动项目 Vite 后访问 `http://127.0.0.1:5180/sunset-street/`。

这是可转动查看的真实三维街道重建。建筑、书架、道路、路缘、人行道砖、树干、树叶、电杆、招牌、电缆、栏杆均有空间几何。天空使用程序绘制的远景纹理，山体使用多层轮廓网格。参考图只在“原图对照”中显示，没有投影进场景材质。

**当前成果是几何与构图重建版本，尚未达到原图的像素级一致。** 主要差距在云层形态、插画笔触、建筑立面细节、树冠轮廓、路面光泽。这里记录可复核的观察、参数依据、实现步骤和实验结果；不把单图无法确定的尺寸与深度描述为真实测量。

用户选择了真实几何路线，并明确排除 `3dviz-pro-max`。后续实现未采用该技能的模板、脚本、数据集或模型。代码使用现有 Three.js/Vite 依赖，无新增依赖；未修改编辑器核心、地图数据或渲染预设。

## M02：图片信息如何映射为空间

### 约束与人工假设

单张图不能唯一解出焦距、相机高度、绝对尺寸与物体深度。这里选定一组可调整、互相一致的假设：

- 图像尺寸 W=1672、H=941。
- 竖直视场角 52°，焦距 f=H/(2 tan(52°/2))≈964.668 像素。
- 相机位置 (0,1.8,0)，朝 -Z；Y 向上。
- 图像主点 (cx,cy)=(954,550)。这是构图拟合参数，不是从 EXIF 得到的镜头信息。
- 地面为 y=0.12z；向远处走时 z 变负，地面下降。
- 地面的理论消失线为 v=cy+f×0.12≈665.76。可见远处道路并不延伸到无限远，城市遮挡会让视觉终点更低。

### 从像素到射线

设 d=-z>0 为点距相机的前向深度，则：

```text
x = (u-cx) × d / f
y = cameraHeight - (v-cy) × d / f
z = -d
```

一个像素只确定一条射线，尚未确定射线上的位置。`atDepth(u,v,d)` 显式保留这个深度参数。

### 用接地条件消除未知深度

将射线上的 y 与坡面 y=-slope×d 联立：

```text
d = cameraHeight / ((v-cy)/f - slope)
```

这就是 `onGround(u,v)`。分母非正时射线不与前方坡面相交，代码拒绝返回虚假的落点。

实际参数示例：

| 对象 | 推定世界坐标 (x,y,z) |
|---|---|
| 左电杆底部 | (-7.058,-1.651,-13.755) |
| 右电杆底部 | (8.829,-2.416,-20.135) |
| 交通灯中心 | (-2.695,5.964,-13.755) |

“灯与左杆共面”是人工建模假设，所以使用左杆的 d=13.755。再将顶部像素代入相同 d，就能得到高度；不必逐个盲调三维坐标。

### Three.js 如何实现偏移主点

```js
camera.setViewOffset(W,H,W/2-cx,H/2-cy,W,H);
```

相机依然水平朝向 -Z，用视窗偏移安置消失点，避免倾斜相机导致建筑竖线收敛。窗口尺寸变化时保持 1672:941 的取景比例，外侧留边，因此不会因手机或窄面板而改变参考构图。

## M03–M11：空间信息如何转译成代码

| 标记 | 图像信息 | 空间表达 | 代码方式 |
|---|---|---|---|
| M03 | 自然变化而非完全重复 | 可复现的差异 | 固定种子随机数；同一种子产生同样的云、叶与书本 |
| M04/M04b | 蓝色天空、金色云缘 | 远景平面 | Canvas 渐变与连续噪声密度场；`sky.js` |
| M05 | 低角度逆光、暖橱窗 | 太阳方向、天空补光、局部发光源 | DirectionalLight、HemisphereLight、PointLight |
| M06 | 下坡道路、收窄斑马线 | 同一坡面上的道路与贴地标线 | PlaneGeometry、旋转 -π/2-atan(slope) |
| M06 | 沥青颗粒、破碎反光 | 漫反射基底与薄水膜分层 | 程序沥青纹理、透明反光碎片；反光为美术近似，非完整反射模拟 |
| M07 | 建筑体量、窗洞、阳台 | 体块 + 凹处暗面 + 窗框 + 突出楼板 | BoxGeometry、窗材质、栏杆 |
| M07 | 发光书店 | 有厚度的开放店面 | 墙、顶、架板、独立书脊、灯带与局部灯光 |
| M08 | 护栏与地砖随深度变密 | 等距世界坐标重复 | 循环安放；地砖合并几何 |
| M09 | 电杆、招牌、电缆 | 地面锚点、共深度构件、下垂曲线 | CylinderGeometry、QuadraticBezierCurve3、TubeGeometry |
| M10 | 不规则枝叶 | 分枝网络 + 数万片有姿态的叶子 | InstancedMesh、每实例矩阵与颜色 |
| M11 | 山脉层叠、远处褪色 | 不同深度的轮廓与城市体块 | ShapeGeometry、远景配色与距离雾 |

通用构件只保留 `box`、`rod`、`plane`、`groundRect` 等少量函数。每个构件具有名称，便于阅读代码及在 Three.js 场景树中识别。

这里没有把“天空噪声”说成真实体积云，没有把美术反光说成路径追踪，也没有将人工估计深度说成单图精确恢复。

## M12：截图反馈如何反过来修改模型

| 轮次 | 实际观察 | 修改 |
|---|---|---|
| 首轮 | 道路向上抬起，与高度函数矛盾 | 修正平面和铺装旋转符号 |
| 第二轮 | 书店画面占比过宽、树冠疏、遮光罩挡灯 | 书店横移、调整树叶尺度与分布、修正遮光罩 |
| 第三轮 | 云像重叠圆团、道路像金属 | 改为连续密度云场；路面拆成漫反射沥青与局部水膜 |
| 后续校正 | 近处右楼过高、树在建筑内部、电杆位于路中 | 减小右楼高度；树移至立面外；右路缘与杆脚协调 |
| 细节轮 | 树冠遮住店招、侧立面缺少空间层次 | 抬高前景树冠，增加侧阳台与栏杆 |

这些是可复核的修订日志，不是完整视觉验收。**关键锚点位置准确不等于整张图准确**；局部误差也不能用一个未经计算的“相似度百分比”概括。

## 使用和构建

- 拖动：旋转；右键：平移；滚轮：缩放。
- 参考视角：恢复标定相机。
- 空间总览：从上方查看真实几何。
- 结构：统一灰材质并隐藏天空与反光。
- 原图对照：显示独立参考图片，再点一次返回场景。
- H：隐藏界面；Escape：恢复参考视角。

在仓库根目录执行：

```powershell
node --test sunset-street/calibration.test.js
node sunset-street/build.mjs
```

构建输出为 `dist/sunset-street/`，可由普通静态 HTTP 服务托管。开发时复用项目 Vite；这不是编辑器地图导入包。

## 检验范围

数学测试用独立的 Three.js 投影矩阵检查像素定位，用接地与回投影检查坡面相交，包含无效射线边界。浏览器检查必须查看真实 WebGL 输出、总览与材质切换。项目测试与构建结果另见 `VALIDATION.md`。

仍有边界：背面按常规建筑结构补齐，未从参考图恢复；背景天空是有限远景平面，转到背向视角后不构成完整 360° 天空；无动态天气、碰撞漫游或物理水面。最重要的未完成项仍是插画级视觉细节与逐像素一致性。
