# 持续地图设计对话

编辑器的“设计对话”维护一段可恢复的对话和一份尚未应用的完整草稿。用户可以在模型工作期间继续输入；新消息中止当前等待中的模型或工具调用，保留上一份完整草稿，再带着已有需求、代码与观察结果继续。

## 运行方式

模型每轮选择一个动作：

- `observe`：读取当前完整草稿的概况、点、区域、路径、物体、资产、世界语义、地形、色卡或按引用保存的执行事实。
- `execute`：执行完整 `function plan(api) { ... }`，或对当前程序做唯一文本锚点替换。每次从会话基底重放，避免重复追加物体。
- `finish`：明确结束为 `completed`、`unchanged` 或 `blocked`。完成修改必须已有完整执行草稿；没有修改或仍被条件阻碍必须说明原因。用户仍可继续同一段对话。

本地 JavaScript 中的环境读取既用于计算，也由执行器同步捕获。`api.report(label, json)` 可回传模型自己计算的决策依据。每次执行的原始查询与报告单独保存，按工具、执行阶段和顺序形成最多 10,000 字符的摘要进入同一模型对话；`observe {kind:"feedback",ref,...}` 可分页读回完整记录。大数组无需每轮重传，摘要截断会明确标记。执行失败也保存已完成的查询，但标记 `applied:false`，不能冒充已应用草稿的状态。观察包含地图版本、草稿版本、坐标单位、采样步长和近似范围。缺失门口数据保持未知，地面坡度与 AABB 不代表角色已经能够通行。

普通场景使用现有 Scene Code 能力。空图可以通过 `api.createWorld({recipe,...})` 创建连续世界，之后普通 `requireAsset/place` 仍能在其上放置设施、道具等独立物体，不局限于聚落建筑或生态树木。已有连续世界使用 `api.worldState()` 和 `api.editWorld(state => { ... })` 修改实际的地形配方、生态规则、道路、聚落和关系。大高度数组留在执行工具中。共同的曲线采样用于环境距离、铺面和草遮罩。

生态规则可显式声明 `exclusions`（最多 32 个圆形或路径区域）。模型可用建筑位置、实际占地和树冠余量计算林间净空；这些区域只排除植被候选中心，不自动推断所有物体的关系。区域观察会返回声明的排除区和采样覆盖率。

执行器不再启动额外的模型修错或资产适配调用。错误与质量诊断返回当前对话，由模型根据用户要求决定下一步。资产请求按完整请求内容缓存到会话，重放使用已生成的真实资产；资产任务数与上游 HTTP 次数分别记录。`maxPaidRequests` 可限制规划和资产的上游派发总数，包括本地重试；并发请求先同步预留额度、持久化后再发出，刷新或重启不会重置。Codex bridge 规划不走付费网关，因此不消耗该计数；计数不估算 token 价格或后端内部计费。

设计对话生成的连续世界使用 `diagnostic` 品质策略：坡度、路面与建筑相交、场地土方量等问题带着对象 ID 和位置返回，不自动改变布局。有限数值、地图边界、引用、版本、容量和已声明的道路端口契约仍须通过校验。旧流程的校验行为不变。这个策略允许保留有缺陷的草稿供讨论，不代表已经验证可通行。

## 应用、暂停与恢复

“修改前 / 当前草稿”复用编辑器的预览，相机不随轮询重置。输入框独立于状态刷新，保留焦点及中文输入状态。

“应用到地图”检查基底地图版本和草稿版本，再提交一次原子事务；撤销对应一次操作。应用后保留原对话，以刚保存的地图为新基底，清空当前执行程序。下一轮只编写相对于新基底的修改。

会话写入当前 MapStore 的 `design-sessions/`。浏览器刷新可以恢复；服务重启后，运行中的会话变为暂停，避免未经用户动作恢复模型调用。手工编辑或其他会话改变地图版本时拒绝覆盖旧基底。

一次需求默认可自主运行 48 个模型动作，创建选项 `maxSteps` 可设 1–128。观察、执行与错误尝试都占用该预算；达到上限时显式暂停并保留未完成草稿，不能称为生成成功。连续三个无效 JSON 响应才停止，前两次格式错误及原输出回到同一对话供修正。累计文本达到 400,000 字符时也显式暂停，不静默截断或用摘要替换原始记录。

## 本地 HTTP 接口

以下接口沿用 `/api/editor` 的访问边界：

| 请求 | 用途 |
| --- | --- |
| `POST /maps/:mapId/design-sessions` | 创建，传 `prompt`、`expectedVersion`，可选模型、资产预算与可用资产 ID |
| `GET /maps/:mapId/design-sessions` | 列出最近会话 |
| `GET /design-sessions/:id` | 状态、进度、公开消息与版本 |
| `GET /design-sessions/:id/draft` | 当前完整地图和操作建议 |
| `POST /design-sessions/:id/messages` | `{ "message": "保留山体，只修改林缘" }`，自动引导当前运行 |
| `POST /design-sessions/:id/pause` | 暂停 |
| `POST /design-sessions/:id/resume` | 继续 |
| `POST /design-sessions/:id/commit` | `{ "expectedRevision": 2, "approved": true }`，原子应用 |

前端用 `?sinceVersion=N` 按状态版本更新记录，未变化时返回 `{ "session": null, "version": N }`，只在草稿版本改变后读取并重建场景。首次恢复遇到临时网络错误会重试，期间不另建会话；确认没有历史会话后停止恢复轮询。切换地图、迟到响应和未保存编辑不会覆盖当前场景。

## 模型连接的实际边界

当前普通模型网关接受累计 `messages`。这里实现的是持久的逻辑对话：需求、操作与事实保留在同一个消息历史中；并未实现服务商保存的 KV 状态，也不能保证网络上不重传历史或自动获得缓存折扣。工具结果通过明确的 JSON 文本封装传回，尚不是服务商原生 function-call 协议。

Codex 插件可以用 `X-WorldForge-Codex-Run` 将规划连接到当前任务模型。会话固定该连接，之后 UI 不带 header 也继续原 bridge；失效时保留草稿并报错，不回退到付费网关。新的有效 header 可显式重新连接。

浏览器截图用于开发验收，生产对话不强制相机回传。渲染方案仍由独立阶段管理，地图修改不自动改变灯光和渲染风格。

## 与已有能力的关系

这次把模型的外层交互归并为观察、执行和结束三个动作；旧版生成入口折叠保留，已有底层场景函数继续供执行程序调用。共享语义来自同一份用户历史、场景程序和实际世界状态，不额外增加互不相通的规划阶段。

连续设计对话使用 `WorldRecipe` 的程序化地形。模型通过 `heightScale`、`reliefProfile`、`landforms`、局部 `terrainBrushes` 和水体控制山形、谷地与雕刻；这些参数仍可由普通 JavaScript 计算。不向该流程开放 `execute.terrainProgram` 或 `api.terrainProgram()` 的整场替换入口，也拒绝在 `createWorld/editWorld` 中绕过入口写入新的替换场。

这个选择来自用户在 2026-10-06 的明确反馈：保留旧 JSON recipe 的粗噪声、山脊和谷地，在其上细化雕刻与聚落；失败的共享高度场没有得到认可。此前工具合同重新开放了替换场，属于错误引入，不能把旧引擎已经存在当成用户同意。旧地图中的高度场仍可读取和渲染，普通编辑可原样保留；更换该场须先回到 recipe。旧会话的草稿与历史保留，但旧替换配置不能继续无提示地执行或提交。

独立旧工具的 513 采样能力保持可选、默认 257，并不进入当前 recipe 生成的默认路径。采样分辨率、流式网格 LOD 和观察查询步长是不同参数，不能把其中一个提高当成全部细节都已提高。城镇 `terrainMode:'conform'` 保留基础山形；旧格式省略模式的默认 `platform` 会整平方形核心并过渡边缘，模型必须知道这个影响，不能把它当成普通建筑接地。

这次没有加入洞穴体积表示、玩法脚本或角色通行求解器。路线坡度、二维连接与支撑采样帮助模型定位问题，不设置逐路步行可达的硬门槛；应结合请求中的玩法理解障碍和可能的通过方式。完整草稿重建仍有渲染成本；对话输入和状态更新与草稿版本分离，不承诺每次场景变化都瞬时完成。

## 同一会话中的整体配色

模型可用 `api.appearance(plan)` 同时声明材质角色源色和环境渲染草案。计划随资产请求传入生成器并参与缓存身份；最终程序重放必须保留发现阶段同一计划。未再次声明时继承当前会话计划，应用地图后也保留。复用资产保持实际原色，资产观察可以读取它们的源色和语义；不能把规划色当成已渲染像素证据。

地图确认后才建立独立待审渲染草稿；进入渲染阶段查看，既不提前应用，也不以新计划覆盖未保存的人工调整。色块在对话面板中可见。

## 反馈与评价

原始事实位于 `design-sessions/<id>/feedback/`；每次执行最多 16,384 条、8 MiB，越界明确报错并保留已取得记录。元数据区分基底版本、草稿版本、是否应用以及 discovery/final；发现阶段可能使用临时资产尺寸。资产生成同时返回 family key、variantIndex、真实 ID、几何和可用的语义信息。无法测得的入口、接触和视觉效果保持未知。

摘要中的较短查询返回完整结构，较大记录返回具体分页地址，不再截取开头一小段 JSON 冒充测量结果。每组仅直接展示首尾记录；省略中间记录、超出总预算或省略大记录时，`summaryTruncated` 都为真。`complete` 只表示原始记录是否完整捕获，与摘要是否完整是两个不同问题。

判断标准见 [地图设计评价](./map-design-evaluation.md)。工具调用成功、物体数量或模型声明结束均不是用户已验收的证明。已经测得的事实、模型的解释和用户确认的目标应区分保存，不能把诊断或建议升级为额外需求。

连续地图的普通 `surface/route/grass` 通过流式地形和内容块适配显示；局部草层使用独立有界采样并保留保存精度，不借用世界的 2×2 占位高度网格。普通笔刷 `paintStrokes` 仍不是连续地表接口，其像素尺寸不能直接当作世界米数；模型应使用语义地表区域。

`observe summary` 分页返回草层样式、可见性及密度采样间距；世界草层最高为 513×513，因此大世界仍可能无法表达窄小草斑，存储密度也不等于已渲染的草叶覆盖。
