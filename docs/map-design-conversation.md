# 持续地图设计对话

编辑器的“设计对话”维护一段可恢复的对话和一份尚未应用的完整草稿。用户可以在模型工作期间继续输入；新消息中止当前等待中的模型或工具调用，保留上一份完整草稿，再带着已有需求、代码与观察结果继续。

## 运行方式

模型每轮选择一个动作：

- `observe`：读取当前完整草稿的概况、点、区域、路径或物体信息。
- `execute`：执行完整 `function plan(api) { ... }`，或对当前程序做唯一文本锚点替换。每次从会话基底重放，避免重复追加物体。
- `finish`：结束当前轮，用户仍可继续同一段对话。

本地 JavaScript 中的环境读取用于计算；外层 `observe` 将结果显式加入模型对话。观察包含地图版本、草稿版本、坐标单位、采样步长和近似范围。缺失门口数据保持未知，地面坡度与 AABB 不代表角色已经能够通行。

普通场景使用现有 Scene Code 能力。连续世界使用 `api.worldState()` 和 `api.editWorld(state => { ... })` 修改实际的地形配方、生态规则、道路、聚落和关系。大高度数组留在执行工具中。共同的曲线采样用于环境距离、铺面和草遮罩。

生态规则可显式声明 `exclusions`（最多 32 个圆形或路径区域）。模型可用建筑位置、实际占地和树冠余量计算林间净空；这些区域只排除植被候选中心，不自动推断所有物体的关系。区域观察会返回声明的排除区和采样覆盖率。

执行器不再启动额外的模型修错或资产适配调用。错误与质量诊断返回当前对话，由模型根据用户要求决定下一步。资产请求按完整请求内容缓存到会话，重放使用已生成的真实资产；资产任务数不是精确的付费 HTTP 次数，底层生成器可能重试。

设计对话生成的连续世界使用 `diagnostic` 品质策略：坡度、路面与建筑相交、场地土方量等问题带着对象 ID 和位置返回，不自动改变布局。有限数值、地图边界、引用、版本、容量和已声明的道路端口契约仍须通过校验。旧流程的校验行为不变。这个策略允许保留有缺陷的草稿供讨论，不代表已经验证可通行。

## 应用、暂停与恢复

“修改前 / 当前草稿”复用编辑器的预览，相机不随轮询重置。输入框独立于状态刷新，保留焦点及中文输入状态。

“应用到地图”检查基底地图版本和草稿版本，再提交一次原子事务；撤销对应一次操作。应用后保留原对话，以刚保存的地图为新基底，清空当前执行程序。下一轮只编写相对于新基底的修改。

会话写入当前 MapStore 的 `design-sessions/`。浏览器刷新可以恢复；服务重启后，运行中的会话变为暂停，避免未经用户动作恢复模型调用。手工编辑或其他会话改变地图版本时拒绝覆盖旧基底。

每次运行最多 12 个模型步骤；达到上限时暂停并保留草稿。累计文本达到 400,000 字符时也显式暂停，不静默截断或用摘要替换原始记录。

## 本地 HTTP 接口

以下接口沿用 `/api/editor` 的访问边界：

| 请求 | 用途 |
| --- | --- |
| `POST /maps/:mapId/design-sessions` | 创建，传 `prompt`、`expectedVersion`，可选模型、资产预算与可用资产 ID |
| `GET /maps/:mapId/design-sessions` | 列出最近会话 |
| `GET /design-sessions/:id` | 状态、进度、公开消息与版本 |
| `GET /design-sessions/:id/draft` | 当前完整地图和操作建议 |
| `POST /design-sessions/:id/messages` | `{ "message": "保留山体，只修改林缘" }`，自动引导当前运行 |
| `POST /design-sessions/:id/pause` | 暂停 |
| `POST /design-sessions/:id/resume` | 继续 |
| `POST /design-sessions/:id/commit` | `{ "expectedRevision": 2, "approved": true }`，原子应用 |

前端用 `?sinceVersion=N` 按状态版本更新记录，未变化时返回 `{ "session": null, "version": N }`，只在草稿版本改变后读取并重建场景。首次恢复遇到临时网络错误会重试，期间不另建会话；确认没有历史会话后停止恢复轮询。切换地图、迟到响应和未保存编辑不会覆盖当前场景。

## 模型连接的实际边界

当前普通模型网关接受累计 `messages`。这里实现的是持久的逻辑对话：需求、操作与事实保留在同一个消息历史中；并未实现服务商保存的 KV 状态，也不能保证网络上不重传历史或自动获得缓存折扣。工具结果通过明确的 JSON 文本封装传回，尚不是服务商原生 function-call 协议。

Codex 插件可以用 `X-WorldForge-Codex-Run` 将规划连接到当前任务模型。会话固定该连接，之后 UI 不带 header 也继续原 bridge；失效时保留草稿并报错，不回退到付费网关。新的有效 header 可显式重新连接。

浏览器截图用于开发验收，生产对话不强制相机回传。渲染方案仍由独立阶段管理，地图修改不自动改变灯光和渲染风格。

## 与已有能力的关系

这次把模型的外层交互归并为观察、执行和结束三个动作；旧版生成入口折叠保留，已有底层场景函数继续供执行程序调用。共享语义来自同一份用户历史、场景程序和实际世界状态，不额外增加互不相通的规划阶段。

地形继续允许模型编写已有 Terrain Program 中的计算函数，自己决定不同尺度的形态。主线已支持显式选择 513 高度场采样；默认仍为 257，避免把更高成本强加给每次生成。采样分辨率、流式网格 LOD 和观察查询步长是不同参数，不能把其中一个提高当成全部细节都已提高。

这次没有加入洞穴体积表示、玩法脚本或角色通行求解器。路线坡度、二维连接与支撑采样帮助模型定位问题，不能替代实际角色验收。完整草稿重建仍有渲染成本；对话输入和状态更新与草稿版本分离，不承诺每次场景变化都瞬时完成。
