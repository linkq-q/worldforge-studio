# 连续地形与多群落大世界实验

日期：2026-09-29。工作分支：`codex/terrain-biome-lab`。基线：`73c335e`。
目标是验证“西方是海洋，东方是沙漠”等方位描述能否控制连续地表，并在 64×64 km 范围浏览多群落。这里只新增实验文件，不改已有地图、地图协议或编辑器入口。

## 结论

技术路线成立：**可见的空间约束 → 全局连续高度/气候场 → 连续群落权重 → 按需分块网格**。当前实现验证了宏观布局、确定性和分块预算；不是已经完成生产级开放世界，也没有把规则解析器当作通用语言模型。

视觉上已经能分辨海岸、沙漠、草原、森林气候区、山地和雪地，边界逐渐混合。近景仍偏平滑，只有地表颜色表达森林，没有树木、真实岩层、河网或侵蚀沟谷。是否符合项目最终美术质量，需要在这个原型上继续验收。

## 与现有项目的关系

现有 `src/shared/map.ts` 的地形上限为 513×513；super 地图预设为 768×32×768。现有 `terrainGeneration.ts` 遍历整张高度数组，适合编辑器当前尺度。

若将 513×513 网格直接放大到 64 km，格距约为 125 m。若保持 1.5 m 格距，全图需要约 18.2 亿个高度样本，单一 Float32 高度层约 7.3 GB，尚不含网格、法线、群落和碰撞。因此本实验不提高既有配额、不改旧地图存储，而是单独验证连续采样与流式细节。

- `src/client/terrainBiomeWorker.ts`：后台生成地块及低分辨率群落图。
- `src/client/terrainBiomeLab.ts`：Three.js 实验查看器、完整覆盖替换、缓存与巡检。

## 生成步骤

1. **解析方位约束。** 东为 +X，北为 −Z，Y 向上，海平面为 0。支持东西南北、四个对角方向和中央；群落支持海洋、森林、草原、沙漠、山脉、雪地。展示解析后的布局；冲突、否定和不支持的语义会报错。
2. **融合大陆与气候目标。** 每个方向有一个锚点，以径向平滑权重影响大陆度、温度、湿度和山地强度。未指定位置保留种子决定的背景场。低频坐标扰动使边界不完全笔直。这里的“气候”是可控视觉模型，不是天气模拟。
3. **生成连续高度。** 大陆度控制海床/陆地；多尺度噪声与平滑山脊生成山体，山地场控制振幅；干燥温暖区域叠加沙丘。局部噪声使用固定米制波长，世界扩大不会把所有局部细节一起拉大。
4. **生成连续群落权重。** 温度随高程下降，湿度与温度决定森林/草地/沙漠；低地海洋和高寒雪地分别参与权重。每点权重非负且总和为 1。颜色连续混合，避免按最大权重直接切换颜色。
5. **按需取样。** 地块只规定采样范围，不改变随机种子或函数定义。33×33 网格从同一个函数取值，法线使用固定 4 m 的全局中心差分，所以共享顶点及法线一致。
6. **预算与替换。** 四叉树优先细化视点附近，最多 256 块。旧覆盖保留到新覆盖完整，再整体替换，避免加载中露洞。稳定缓存最多 384 块，转换中最多 512 块。跨精度边缘使用裙边遮缝，不是严格的边缘拼接或 geomorph。

可复制的输入：

```text
我希望西方是海洋，东方是沙漠
西方是海洋，东方是沙漠，北方是雪地，南方是森林，中央是山脉
北方是海洋，南方是沙漠，西方是森林，东方是草原，中央是山脉
西北是海洋，东北是雪地，西南是森林，东南是沙漠，中央是草原
```

配方中保存 `version:1`、`seed`、米制范围和方位约束。相同版本算法、配方和坐标得到相同结果。版本号不是对未来任意算法修改的兼容承诺。

## 已知限制与下一步

- 方位模板不是任意自然语言理解。下一步可让现有 Agent 直接生成并校验相同配方；先显示约束再执行，避免模型逐点生成高度。
- 森林当前是温湿度与地表权重，没有树；现有截图不能当作完成的生态美术。下一步用同组权重及坡度，在局部块上生成确定性植被与岩石。
- 没有真实雨影、河网、泥沙输送或侵蚀。下一步先生成低分辨率全域水文约束，再让局部块查询；不要每块独立侵蚀，否则上游与边界不连续。
- 全局采样函数连续不等于不同 LOD 的三角网格完全吻合。目前裙边会掩盖裂口，仍可能有轮廓跳变和远处欠采样。正式采用前需边缘拼接/形变、抗混叠与连续移动验收。
- 相近方向约束可能竞争；本版只拒绝同方位直接冲突，不是通用空间约束求解器。导出的配方便于复现和诊断。
- 地图有固定范围，不是无限流式世界。没有远原点重定位、地形编辑持久化、导航、碰撞或网络层。
- 正式融合回编辑器，应先决定分块配方与局部编辑数据的协议，再沿用单次 `MapOperation[]` 原子事务、版本校验和一键撤销，不应把整个大世界塞回旧 513×513 数组。


## 在 64 km 世界中放置景物的性能判断

当前原型尚未调用原编辑器的景物规划或散布；地形帧率不能外推为海量景物帧率。

核查本分支源代码：

- `mapScatter.ts:138–139`：概率场单次最多 512 个结果、4096 个候选，因此不会因面积自行无限采样，但覆盖大世界需要很多调用；单纯保持配额会让内容很稀。
- `mapScatter.ts:181`：点间距检查线性扫描已接受点。单次规模有界，但不能简单把上限扩大到百万。
- `mapScatter.ts:239–244`：传统 scatter 先生成整个区域包围方格的 `cells` 数组并打乱，再在 `246–247` 检查 `maxCount`。因此小输出配额不能阻止巨大候选数组的分配。举例：64 km 宽的包围方格、10 m 格距约 4096 万个候选格；这是规模推算，未执行这种高风险分配。
- `mapScatter.ts:281`、`mapPlacement.ts:143`：占用/碰撞检测有逐项 `some` 扫描，大量对象会提高候选验证成本。
- `mapLimits.ts:2`：Scene Code 总放置上限为 100,000。这个上限是安全限制，不是已经验证可流畅绘制 10 万任意模型。
- `mapPlanning.ts:48–50`：室外旧路径物体预算按 area/90 增长；64 km 方形若直接套用，约 4551 万个。这不等于实际会全部生成，各路径另有限制，却说明现有面积公式不应直接用作大世界预算。
- `mapRenderer.ts:241–275`：遍历地图对象建立分组、实例化批次和其余视觉对象；已有批处理与剔除，并不是每棵树一定一个 draw call，但初始对象列表、构建、持久化与碰撞仍不是按需世界流式链路。

建议沿用当前 AI 的表达能力，但将执行范围分层：

1. 世界规划：群落边界、道路、城镇、地标、疏密规则；不枚举每一棵树。
2. 局部规划：仅对城镇或特定景观点调用现有布局规划器。
3. 自然景物：以固定世界网格分块，用世界 seed、块坐标、资产类别生成可复现候选，再读高度、坡度和群落权重筛选。相邻块使用共享候选规则及边缘邻域，避免跨块重叠。
4. 运行时：近处完整实例和必要碰撞，中距简化实例，远处使用地表/树冠近似；离开后卸载。碰撞与最近邻使用局部空间索引。
5. 存储：保存生成规则、种子、手动增删等差异，而非全世界自然物体坐标。手工地标仍保留明确对象和编辑事务。

256–512 m 可作为景物分块的测试起点，不是已测出的最优值。景物块应有稳定身份，不跟随地形 LOD 叶节点改变，否则镜头缩放会改变树的位置。下一步应先用一个森林区，分别测生成耗时、候选拒绝率、活动实例数、GPU 帧时间、碰撞成本和跨块移动，再决定预算。
