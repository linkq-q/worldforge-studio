# 地标建筑 API 拼装对照

本批替代整张村落的观感比较，回答：在相同 DeepSeek 构件下，增加一个拼装 API 是否改善地标建筑的结构接合，同时保留辨识轮廓。

- 案例：天坛祈年殿及三层圆台；完整时期罗马斗兽场的结构复原示意。
- 配置：固定资产精简放置、额外开放 `placeBetween`、额外开放 `attach`。每个案例每种配置重复两次，共 12 张。沿用原 `rounds.json`，先前 38 次和失败均计数，总上限仍为 50。
- 每个案例由 GPT 单独规划 10–16 类结构构件，DeepSeek 生成一次，所有配置与重复共用同一套实际几何。复用轮次新生成资产数为零，不能记成每轮新生成 10–16 个。未调用 API 的样本保留，不能当作该 API 实际效果。
- 固定平地与 96×48×96 地图；不得调用地形、背景装饰或资产再生成 API。只允许使用公共构件及同一尺寸资料；每种配置只增一段可选 API 说明，不强制使用。
- 规划均为 GPT、temperature=0.25、首次代码执行、只诊断不自动修复。所有地图用同一进程中的执行器与 MapStore 原子事务保存；记录源文件快照、哈希、构件几何哈希、提示、代码、实际调用、诊断和失败。
- 中途磁盘源码变化记录为并行编辑，不热替换进程已加载的执行器。跨进程续跑时，若已有成功样本，要求执行源码哈希一致。
- 单一 HTML 按建筑、轮次、API 分组；每张真实渲染俯视和 45° 透视，点击可放大。构件数、物体数、诊断数都不是审美评分。

观察标准：地标的主要轮廓与比例、层级与内部留空、入口可辨识、重复构件接缝、各层承托、错层/悬空/穿插。祈年殿重点看圆形殿身与三重蓝瓦檐、三层白石台的层级；斗兽场重点看椭圆空场、环廊、拱券楼层与看台之间的关系。

本批不测资产拆分的优劣，也不测完整全规划提示的收益。固定构件可能偏向某种组合策略；两个重复只用于筛选线索。不能由此推断某 API 限制地形、所有复杂建筑都受益，或精简模式整体最优。

建筑资料：[北京市公园管理中心：祈年殿](https://gygl.beijing.gov.cn/mlgy/mlgy_gyjg01/201912/t20191211_1048233.html)、[罗马斗兽场考古公园](https://colosseo.it/en/area/the-colosseum/)。属于识别性低多边形实验，不声称文物级精确复原。

运行：`node --import tsx scripts/runLandmarkAblation.ts <existing-absolute-experiment-directory>`。截图沿用 `scripts/apiAblationPreview.html`，传入 `framing=landmark`；旧山地截图的默认相机不变。
