# 地标拼装复测 v2

用户于本任务中追加授权 20 次，总账上限由 50 增至 70。旧样本和失败记录保留；不覆盖旧代码、截图、提示或资产。旧实验受到旋转单位错误和关闭自动拼接的影响，不纳入 v2 效果比较。

祈年殿、斗兽场各做基础放置与额外开放 placeBetween 两种条件，各重复五次。每座建筑沿用原有 DeepSeek 构件及几何哈希，新增资产为零。GPT、temperature=0.25、提示全文、地图种子、地图尺寸和自动修复策略在同一条件的五次重复中保持不变。地图种子不是模型采样种子；本地请求固定 provider，但不声称锁定远端服务内部模型版本。

修正 rotationY 为弧度并给出坐标约定。两组都启用正常空间修复。每份模型代码在内存分别以 diagnose 和默认修复运行，保存修复前后建议和变换差异；仅默认修复结果通过一次事务保存为地图。这种重复执行不调用模型、不额外生成地图。新增 API 不强制使用；未采用单独记为未采用，不能作为 API 执行效果。

生成前以真实的现有 DeepSeek 拱券资产进行 24 段闭环内存校准，另有弧度契约与额度回归测试。校准不调用模型、不保存地图、不计入新增 20 次。它验证执行链，不代替视觉验收。

每张保存俯视及 45 度视图，统一相机，离线 HTML 按建筑、轮次、配置分组，展示实际 API 调用和修复量。记录失败，不补抽到成功，也不把物体数量作为质量分。五次是初步重复观察，并非统计充分性的保证。

生成期间用户明确选择“不修复为主，修复后作辅助对照”。验收页因此主展示 diagnose 操作在内存应用后的结果，折叠展示相同 GPT 代码经自动修复后的截图，共 80 张截图。编辑器中保存的地图仍是修复后版本，两者在页面明确区分。没有额外模型请求，也没有增加地图生成轮数。为保留五次相同输入，未中途更改提示中“会自动修复”的说明；该条件是本批推断的局限。

保存校验最初误拒绝了自动修复产生的 object.update。恢复脚本只重放已返回的原始代码，核对执行器源码哈希及 DeepSeek 几何哈希，确认更新对象均由本次事务新增，再以一笔事务保存。原错误保留在独立恢复日志和每轮 harnessError 中，不把恢复计为新的模型样本。

运行：`node --import tsx scripts/runLandmarkRepeats.ts <原实验目录绝对路径>`。脚本在每次请求前占用额度，保留生成代码。执行期间单进程固定已经加载的源代码；工作区并行改动另存记录，不切换到热更新执行器。完成 20 次或总计 70 次后停止。
