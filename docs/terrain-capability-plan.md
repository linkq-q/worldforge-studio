# 可组合地形能力任务书

## 目标

扩展地形编辑器的地形种类，并让手动编辑、地图 AI、外部 Agent 与 CLI 共用同一套确定性地形能力。整体预设只能是能力组合的便捷入口，不能把峭壁、梯田、沙丘或小岛算法封闭在某个固定预设中。

第一版完成后，Agent 应能把自然语言意图编译为有序能力组合。例如“生成高山梯田，东侧带海岸峭壁”应拆成：

1. 生成高振幅丘陵基底；
2. 对指定区域应用梯田修改器；
3. 沿东侧路径应用海岸峭壁修改器；
4. 生成海面并处理贴地对象；
5. 使用现有预览、确认和单步撤销流程提交一个事务。

## 当前基线

- 共享地形生成已经支持 `plain`、`hills`、`valley`、`island`、`canyon`。
- 编辑器地形面板目前只提供抬高、降低、平整笔刷，没有手动暴露整体生成预设。
- 基础生成使用地图 `seed` 确定性烘焙高度场；地图 AI 已能输出 `terrain.generate`。
- 地图与渲染是两个阶段：地图先预览并确认，之后才能选择或生成渲染方案。

## 核心设计

### 共享能力表

建立一份由共享模块拥有的静态地形能力表，供 UI、地图 AI、外部 Agent、服务端校验和 CLI 共同读取。暂不建设运行时插件系统，也不允许 Agent 在地图生成过程中修改项目源码。

每项能力至少声明：

- 稳定 ID、中文名称和用途描述；
- `base`、`modifier`、`surface` 或 `render-effect` 分类；
- 接受的区域类型和参数范围；
- 执行阶段与排序约束；
- 是否替换整个高度场；
- 是否会派生水体、垂直岩壁或渲染建议。

AI 提示词、参数校验和编辑器选项必须从这份共享能力定义派生，避免在多个位置维护不同的地形名称清单。

### 能力分类

1. **基础生成器**：建立整张地图的基础高度场。
2. **局部修改器**：在有界区域或路径内修改已有高度场，可以按顺序组合。
3. **地表能力**：描述草地、沙地和岩地等地图表面语义，不包含最终天空、雾或后处理风格。
4. **渲染效果**：读取已确认地图的语义，在渲染阶段提供飞沙等效果。

局部修改器第一版接受三种区域输入：

- 圆形：局部小岛、盆地等点状结构；
- 路径：峭壁、山脊、海岸边缘；
- 封闭区域：梯田区、沙丘区和沙漠地表。

暂不支持用户上传任意遮罩图。

## 第一版范围

### 整体地貌入口

编辑器暴露现有基础地貌：

- 平原；
- 丘陵；
- 山谷；
- 小岛；
- 峡谷。

新增两个整体地貌组合：

- 峭壁高原；
- 沙丘荒漠。

“高山”第一版由高振幅丘陵基底与峭壁修改器组合，不新增仅供高山预设调用的私有算法。后续可在证明当前形态不足后增加专用山脉生成器。

### 局部地貌能力

- 峭壁修改器；
- 梯田修改器；
- 沙丘修改器；
- 局部小岛印章。

操作方式按能力区分：

- 小岛等点状结构使用单击印章；
- 峭壁、梯田和沙丘支持沿路径或区域绘制。

### 地表能力

- 草地；
- 沙地；
- 岩地。

沙漠默认组合沙丘高度与沙地地表，但不自动放置枯木、绿洲或建筑，也不在地图确认前应用最终渲染方案。

## 峭壁与梯田

### 支持的峭壁布局

峭壁能力必须可以独立用于：

- 高原边缘；
- 海岸峭壁；
- 峡谷两侧；
- 独立岩壁；
- 多层阶地。

这些布局共享峭壁修改核心，通过路径、作用方向、层数和区域约束表达，不复制五套完整算法。梯田保留为独立修改器，负责重复分层和平坦区域；每层边缘复用峭壁能力。

### 混合地形表示

第一版同时支持陡坡近似和可选的真正垂直岩壁：

- 高度场继续负责崖顶、崖底、地形笔刷、坡度分析、植被与水体刻蚀；
- 峭壁能力可沿断崖边缘确定性派生垂直岩壁网格；
- 垂直岩壁参与射线选取、资产避让和碰撞计划；
- 垂直岩壁不是普通可移动地图对象，用户修改来源地形后应重新派生；
- 本阶段不把整个高度场替换成任意三角网格，也不支持悬洞和倒悬地形。

## 沙漠与飞沙

第一版沙漠包含：

- 连绵沙丘；
- 岩石荒漠；
- 沙地地表语义。

飞沙属于渲染阶段，不写入基础高度场，也不绕过地图确认流程。已确认地图中的沙地区域可向渲染阶段提供效果建议：

- 地表流沙 Shader；
- 受沙地区域限制的低空飞沙粒子或粒子 Shader；
- 普通用户只调整关闭／微风／强风、风向和强度；
- 默认效果轻量，不遮挡编辑视线；
- 第一版不包含覆盖整张画面的沙尘暴。

新增 Shader 必须遵守现有渲染权限阶梯，通过受限渲染能力和方案权限开放，不能让 AI 直接修改 Shader、uniform 或任意 Three.js 对象。

## 小岛与水面

第一版支持：

- 单一主岛；
- 群岛组合。

生成小岛时自动加入海面；地形、水面和必要的贴地修正必须出现在同一个预览与事务中。小岛不应只是边缘较低但没有可见水面的高度场。

## 应用于已有地图

应用整体地貌时：

- 必须先预览；
- 替换基础高度场，但保留已有对象；
- 跟随地形的对象重新贴合新高度，固定高度对象保持原设置；
- 不静默删除已有对象、水体或地表绘制；
- 结构化水体在基础生成和局部修改之后重新执行必要的盆地刻蚀；
- 整批变化作为一个 `MapOperation[]` 事务提交和撤销；
- 应用后仍可继续使用局部地貌和普通地形笔刷。

## 参数与随机性

普通用户只看到：

- 规模；
- 高度或强度；
- 边缘柔和度；
- 方向；
- 随机变化。

默认结果由地图 `seed` 确定。“换一个”只改变本次能力使用的派生 seed；相同地图、相同参数和相同 seed 必须生成相同结果。第一版不向普通用户暴露噪声层数、频率和衰减等实现参数。

## 编辑器组织

不要求增加复杂页签。现有地形面板内分成三个清晰区段即可：

1. 基础地貌：明确提示会重新生成整张高度场；
2. 局部地貌：只作用于用户绘制或 Agent 指定的区域；
3. 地表：只改变草地、沙地和岩地等地图语义。

这样可以避免把破坏性不同、参数不同的操作混入同一列表，同时保持一个地形编辑入口。

## Agent 行为

- 保持当前“规划 → 内存应用 → 预览 → 用户确认 → 单事务保存”模式。
- Agent 可以选择一个基础生成器，再组合多个有界局部修改器和地表能力。
- 能力必须按确定性顺序执行：基础地貌、局部修改、结构化水体刻蚀、贴地与派生网格重建、质检修复。
- Agent 找不到完全匹配的能力时，先组合已有能力；仍无法满足时必须在预览诊断中明确说明，不能按名称猜测后静默替代。
- Agent 不直接输出任意高度坐标、运行时代码、Shader 代码或未注册能力。

## 不在第一版范围

- 把整个地形系统改成任意三角网格；
- 悬洞、倒悬岩体和体素挖掘；
- 动态第三方地形插件；
- 用户上传地形遮罩图；
- 完整沙尘暴；
- 沙漠资产和绿洲的自动场景包装；
- 在地图确认前自动应用渲染方案；
- 强制制作特定金样或人工验收场景。

## 实施顺序

1. 把现有基础地貌定义收拢为共享能力表，并让校验与 AI 描述从该表派生；
2. 在编辑器中暴露现有整体地貌，接入预览、确认和事务；
3. 增加峭壁、梯田、沙丘与局部小岛修改器及区域输入；
4. 增加确定性垂直岩壁派生网格、射线选取和资产避让；
5. 接入沙地与岩地表面语义；
6. 接入渲染阶段的地表流沙与低空飞沙能力；
7. 让地图 AI、外部 Agent、UI 和 CLI 共用能力表，并补齐端到端验证。

## 完成标准与验证

- 每项地形算法可被独立调用，也可按顺序组合，不依赖某个固定整体预设。
- UI、AI、Agent、服务端校验和 CLI 使用同一组能力 ID 与参数范围。
- 相同 seed 和参数生成完全一致的高度场、派生峭壁和水面结果。
- 能证明“高振幅丘陵 → 梯田 → 海岸峭壁 → 海面”组合不是专用硬编码预设。
- 整体地貌应用到已有地图时保留对象，并正确更新跟随地形的对象。
- 垂直岩壁参与选取和资产避让，来源地形改变后可确定性重建。
- 沙漠地图阶段只保存地貌、地表语义和渲染建议；飞沙只能在地图确认后的渲染阶段启用。
- 非法能力、非法区域、越界参数和超过配额的组合在应用前被拒绝或裁剪，并给出明确诊断。
- 新增共享逻辑具有可失败的确定性、组合顺序和边界测试。
- 执行 `npm test` 与 `npm run build`；编辑器改动还要验证本地 API、预览/确认/撤销流程和可见浏览器效果。
